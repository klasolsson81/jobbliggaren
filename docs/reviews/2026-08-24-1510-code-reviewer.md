## Major

### 1. Den nya e2e-spec:ens positiva kontroll påstår ett antal sidan inte kan producera — samma defektklass som PR #1504:s Major 1

`web/jobbliggaren-web/tests/e2e/jobb-live-region.spec.ts:47` (+ docblock `:23–26`)

```ts
const FILTER_REGION = "p[aria-live='polite'].sr-only:not([aria-atomic])";
await expect(page.locator(FILTER_REGION)).toHaveCount(1);
```

`/jobb` renderar **två** element som matchar den locatorn efter hydrering:

- `src/components/job-ads/job-ad-typeahead.tsx:287` — `<p id={statusId} role="status" aria-live="polite" className="sr-only">`, ovillkorlig i typeaheadens träd
- `src/components/job-ads/jobb-hero-search.tsx:668` — `<p role="status" aria-live="polite" className="sr-only">`

Ingen av dem bär `aria-atomic`. Typeaheaden renderas på `hydrated` (`jobb-hero-search.tsx:579`, `useSyncExternalStore` `:148`) — alltid sant i en riktig browser. **Repot dokumenterar redan detta självt:** `jobb-hero-search.test.tsx:232` — *"OBS: det finns TVÅ polite live-regioner runt fältet (typeaheadens + heron:s)."* `toHaveCount(1)` ser 2.

Ingenting rapporterar det: `vitest.config.ts:14` inkluderar bara `src/**` + `scripts/**`, och e2e-lanen är `continue-on-error`. Deltats enhetssvit kan aldrig se det heller — `page.test.tsx:73` mockar bort `jobb-hero-search`.

Detta är **samma fynd som `docs/reviews/2026-08-24-foretag-sok-live-region-code-reviewer.md:50–64`** ställde på #1504: en `toHaveCount(1)` som såg 2 på en lane som inte säger ifrån. Fixen skärpte `LOAD_REGION` korrekt och lämnade den andra selektorn omätt.

Krävs: skopa den positiva kontrollen till heros egen region (eller mät 2 med skälet utskrivet), och rätta docblockets *"would otherwise resolve to two elements"* — det är tre `p`-regioner på sidan. AGENTS.md §7, §8 DoD 2.
