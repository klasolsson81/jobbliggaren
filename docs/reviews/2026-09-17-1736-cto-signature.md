### Beslut

**Form A — ADR 0142 D6 exactly as written:**
`JobSeeker.Register(Guid userId, string? displayName, TermsAcceptance acceptance, IDateTimeProvider clock)`, **replacement, not overload**. `DisplayName` keeps its current non-nullable column, its `ValidateDisplayName` invariant and its event payload untouched in 1b. Parameter order is D6's — `clock` stays last, which is the aggregate's own convention (`JobSeeker.cs:150` `UpdateDisplayName(displayName, clock)`, `:161` `UpdatePreferences(preferences, clock)`).

**And the general bind that settles this class of conflict without re-litigation:** where a ratified ADR and an issue body disagree, **the ADR governs and the issue body is corrected**. ADR 0142 is Accepted, was authored *after* #1736/#1741, and #1736's own body names it as its design source ("Design: epic D6"). The issue bodies are derived artefacts.

### Motivering mot principer

- **Aggregate invariants are enforced by construction, not by convention (Evans 2003, "Factories"; Vernon 2013, "Rule: protect business invariants inside aggregate boundaries"; AGENTS.md §2.2).** Form B forces a two-step construction — `Register(...)` producing a nameless aggregate, then `UpdateDisplayName(...)` — which demotes the #1117 personnummer invariant (`JobSeeker.cs:81-107`, the repo's self-declared "highest-priority PII rule") from a constructor guarantee to a caller convention **in the very commit whose purpose is to make the consent stamp a constructor guarantee.** That is self-contradictory: D6's whole argument for "replace, not overload" is that a convention is not an invariant. You cannot spend that argument on consent and violate it on the name in the same method.
- **CCP — things that change for the same reason belong together (Martin 2017, kap. 13).** Two change-reasons: "a new seeker carries a consent record" (D6, part 1b) and "the account has no name" (D7, parts 4a/4b, which #1741 itself gates on 1c + 3b — *"nothing collects or renders the name any more"*). Form B fuses them and drags 4a's `DisplayNameNullable` migration forward.
- **Serial migration order in the most dangerous hotspot (CLAUDE.md §6.5).** 1b is the **first** migration of 1b → 6d → 4a → 4b → 5b. Form B makes that first migration carry a second, unrelated schema relaxation whose consumers are not ready: `/registrera` still collects and posts the name (`web/jobbliggaren-web/src/lib/auth/actions.ts:154,171,189`) and `RegisterCommandValidator.cs:20` still requires it. Schema ahead of consumers, in the single-owner hotspot, is the one place the repo has written down that it does not do.
- **YAGNI/KISS cuts toward A, not away from it.** Form B's only real benefit is sweeping the test call sites once instead of twice. That is tempo, and CLAUDE.md §9.6 is explicit that quality outranks it (Regel 1 / Mastercard-test).

### Avvisade alternativ

**Form B1 (#1736's signature + 4a's migration pulled into 1b, `Register` writes null, handler calls `UpdateDisplayName`).** Rejected. It converts a constructor invariant into a caller obligation; it changes the public API contract (`acceptTerms`/`displayName` validation) in a part whose own scope says it must *not* touch the page — #1736's text: "so the current flow stops losing it **before part 2 replaces the page**"; it makes `JobSeekerRegisteredDomainEvent.DisplayName` (non-nullable `string`, `Events/JobSeekerRegisteredDomainEvent.cs:9`) either null-bearing or a lie; and it bypasses the dependency #1741 declares on itself. It also leaves a persisted-with-null failure mode if any future caller forgets step two — the exact fail-open shape `ValidateDisplayName`'s comment says it exists to prevent.

**Form B2 (keep NOT NULL, write a placeholder).** Rejected on sight. `DisplayName` composes into `PersonalInfo.FullName` — the header of the PDF the user sends to employers (`JobSeeker.cs:83-85`). Writing a synthesised value there is CLAUDE.md §5's "synthesising prose the user did not write", in the one column where it reaches an employer.

**Variant C (introduce a shared test factory/builder in 1b so future signature churn never sweeps again).** Rejected for 1b. It is itself a 142-file cross-cutting edit, fused into a migration PR, for a benefit that is one scripted commit later in the epic. Not filed as an issue either — see below.

**Amending ADR 0142 D6 to #1736's signature.** Rejected. The ADR is both later and more coherent; amending a ratified design to match an issue body written before it inverts the direction of authority and would have to re-open D7's sequencing at the same time.

### Trade-offs accepterade

- **One extra mechanical sweep across the epic.** Under A, `displayName` survives in the signature through 1b/1c/6d and is removed at 4a or 4b, costing a second compiler-driven sweep of the same call sites. Accepted: two reviewed mechanical commits, each landing with its own change-reason, beat one commit that fuses two. This is the single axis on which an override would be rational — if Klas values one sweep over sequencing safety, say so and 1b becomes B1 **with 4a's migration and #1741's 1c/3b dependency explicitly re-scoped first**.
- **Three prose corrections now** (ADR cost sentence, two issue bodies) instead of zero. Cheap, and each is a deletion plus a dated fact.
