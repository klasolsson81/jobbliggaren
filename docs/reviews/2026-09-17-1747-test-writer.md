### Major 1 — `Down` runs only against an empty table, and the restored column default is not asserted

The journey order was head → previous → (insert) → head, so the row landed **after** `Down`.
`Up` against a populated table: covered. `Down` against a populated table: **not covered at all**
— the rollback ran against zero rows. That is exactly the half the docblock itself calls the
operator's only way out.

**Two mutants survive in that form:**

- **M5a** — remove `defaultValue: "Local"` from `Down`'s `AddColumn`. Against an empty table: OK →
  **test green**. Against a populated table: `ERROR: column "provider" ... contains null values` →
  **the rollback fails in production**.
- **M5b** — change `defaultValue` to `""`. The test never reads `column_default` and has no rows at
  `Down`, so → **green**. In production every account is stamped `provider = ''`, and the
  rolled-back image (whose `HasConversion<string>()` targets the enum) throws on every user read.
  Total auth outage *during* a rollback.

Both die from **one** change: move the insert to after step 1, and widen `ColumnShape` with
`column_default`.

> **Escalation, verbatim:**
> "Down körs mot en tom tabell och `column_default` läses inte. Två mutanter överlever:
> `defaultValue: "Local"` borttaget ur `Down`s `AddColumn` (grönt i testet,
> `ERROR: column "provider" of relation "AspNetUsers" contains null values` vid rollback av en
> populerad tabell) och `defaultValue: ""` (grönt i testet, varje konto stämplas `provider = ''`
> och den tillbakarullade imagens enum-converter kastar på varje användarläsning). För en
> destruktiv migration mot PII-tabellen är Down säkerhetsnätet, och säkerhetsnätet är otestat mot
> rader."

### Major 2 — the §5 paragraph names the wrong writer and offers a "pin" that is not a pin

**(a) HOLDS.** What the assertion rests on is a row existing and surviving `Up` — produced by
`UserManager.CreateAsync`. §5 says explicitly that a raw `INSERT` carries no obligation when the
state it creates is one `src/` does produce.

**(b) HOLDS ON THE VALUE, BUT THE WRITER IS MISNAMED.** The snapshot at `d90414f3` registers
`Provider` as `.ValueGeneratedOnAdd()` with `.HasDefaultValue("Local")`, and the migration put a
`DEFAULT 'Local'` on the column. `AuthProvider.Local = 0` **is** the sentinel, so EF omitted the
column from the INSERT and the **DB default** wrote the value. The field initialiser is what makes
the CLR value *resemble* the sentinel — that is, precisely what stops the CLR side from writing.
And it is not cosmetic: the real writer is the column default, **exactly what `Down` restores and
what Major 1 shows the test does not assert.**

**(c) DOES NOT HOLD — and does not need to.** §5's retired-actor branch opens only *"where that
state is produced by no path in `src/`"*. Per (a)+(b) it **is** produced by a path in `src/`, so
the test owes no pin at all. And what is offered is not a pin: §5's pin is a **test**; a migration
asserts nothing, and *"after `Up` the columns do not exist"* is a tautology about the schema.
**Graded Major and not Minor because the sentence reads as precedent.**

**Not a §12 STOPP**, and that should be said plainly: §5 imposes no disclosure duty here, so a
voluntary and incorrect disclosure routes as `Comments:` — §12's one explicit carve-out.

> **Escalation, verbatim:**
> "Premissen håller — raden existerar och `UserManager.CreateAsync` producerar den. Motiveringen
> håller inte. `ApplicationUser.Provider`'s field initialiser var inte kolumnens skrivare;
> snapshotten vid `d90414f3` rad 87–93 visar `.ValueGeneratedOnAdd()` + `.HasDefaultValue("Local")`,
> så DB-defaulten `DEFAULT 'Local'` skrev värdet — samma mekanism som `CreatedAt`-kommentaren i
> samma configfil beskriver. Och retired-actor-grenen i §5 öppnar bara 'where that state is produced
> by no path in src/', vilket den inte är här, så testet är inte skyldigt någon pin — varpå det som
> erbjuds som pin ('after `Up` the columns do not exist') är en tautologi om schemat och inte ett
> test. Meningen riskerar att citeras som prejudikat av nästa test som genuint behöver grenen."

### Minor 1 — two of the docblock's three hazard mechanisms do not exist

*"a cascade off the dropped unique index"* — `DROP INDEX ... CASCADE` drops dependent objects,
never rows. *"a name that does not match is a silent no-op"* — EF generates `DROP INDEX` without
`IF EXISTS` → 42704, migration aborts. That is the loudest possible failure. **The session's
mutant 2 went red by abort, not by a surviving index — so the mutant never validated the claimed
mechanism.**

### Advisory (no action requested) — `Down` restores schema, never data

Acceptable only because of the measurement that no other value was ever written. **No change
requested:** the only cure would be added prose, and §9.6 says a finding closable only by new prose
closes by deletion or goes to STOPP.

### Answers

**Q1 — one case missing; the guessed ones should NOT be written.** `Down` against a populated table
+ `column_default` is the hole. Multiple rows add nothing (`DROP COLUMN` is table-level DDL). A row
with `provider_user_id` NOT NULL is **the §5 trap** — nothing in `src/` ever assigned it.
`__EFMigrationsHistory` is covered indirectly. Concurrency is an ops note, not a test gap: `DROP
COLUMN`/`DROP INDEX` take ACCESS EXCLUSIVE, no `lock_timeout` is set, and server `statement_timeout`
is `0` — inert today with two accounts, but it belongs in the deploy runbook before launch.

**Q3 — deleting `AuthProviderDefaultsTests` is not coverage loss.** Its subject was deleted with the
columns. The endpoint keeps 15 other test files; the filtered unique index had *no* test before this
PR; and the mechanic the test incidentally exercised (a DB default stamping through the real write
path) keeps an oracle in `HardDeleteAccountsJobIntegrationTests:209`. **Right call. An empty stub
would have been worse.**

**Major 1:** both oracles sit. M5a now dies on the migration itself (the row is in place before the
rollback, so Postgres rejects the step); M5b dies on **two independent** assertions — one a schema
oracle, one a data oracle. `'Local'::character varying` is the right normal form. **The ordering
gives more than I asked for:** `Up` in step 4 runs on rows *and* `Down` in step 3 runs on rows.

**Major 2:** the paragraph is deleted, not rewritten. And the premise is gone in substance, not just
in prose — `InsertUserAsync` writes only columns that exist at head. **Every sentence the fix adds
was grepped**; the replacement text holds.

**Outside my findings: the delta fixed an error I missed in round 1.** The old docblock said the
test runs *"as the role production migrates with"*. `MigrateLog.cs:200` —
*"Mode: bootstrap (Identity-context via master-creds — ADR 0034)"*. Production applies the Identity
context under **master credentials**. The new wording is correct. **Good catch by the session.**
